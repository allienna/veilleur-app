# Veilleur-app — Design System

**Last updated**: 2026-05-19
**Status**: Living document
**Surfaces covered**: `pwa` (primary), `astro-site` (external, token-aligned), `minion` (logs only)

## 0. Identity

**Mood**: calm, trustworthy, precise. Morning-routine product the operator trusts at a glance. Never playful, never noisy, never decorative.

**Brand inherited from `allienna.github.io/veilleur`** (Astro site) — same palette, same fonts, same mascot so an article reads identically in the PWA and on the public site. Interaction patterns diverge: the PWA uses iOS-native shadcn primitives (see §2 inventory) instead of Astro's article-page layout.

**Mascot**: 🦉 *Le Veilleur* — navy owl with amber eyes, Pixar style, 16:9. Generated by Imagen 4 Fast per article; never used as a UI illustration outside the hero image of a published article. The header glyph in the PWA shell is the emoji `🦉` on an amber-tinted circle (see Astro `BaseLayout`).

**Locale**: French (BCP-47 `fr-FR` on the web surface — see §5 for the full convention). All UI strings in French.

### Forbidden

These tempt but are not in the inventory; their absence is intentional:

- **`Modal` / `Dialog`** — use `Sheet` (iOS-native bottom slide). Centered dialogs feel wrong on iPhone home-screen-installed PWAs.
- **`Tabs`** — top nav covers the three main views; nested tabs add navigation depth the operator doesn't need.
- **`Drawer` (side)** — single operator, no need for a hamburger; AppHeader is wide enough.
- **`Tooltip`** — no hover on iOS; surface the label inline instead.

## 3. Layout Patterns

### Surface: `pwa` (primary)

- **Viewports**: iPhone 12-mini (375px) → iPhone 15 Pro Max (430px) → iPad portrait (768px) → Mac Safari (≤1280px container).
- **Primary persona**: Aurélien (operator).
- **Density**: `regular` for `/` (Today reading), `compact` for `/history` and `/runs/[id]` (supervision).
- **Navigation**: top sticky `AppHeader` with three nav targets — `Aujourd'hui`, `Historique`, `Supervision`. No bottom tab bar (preserves visual lineage with the Astro site's header-only chrome).
- **Container**: `max-w-3xl mx-auto px-4 sm:px-6` for reading. Supervision views allow `max-w-5xl`.
- **Safe area**: respect `env(safe-area-inset-top/bottom)` on the AppHeader and any `Sheet` so the home-screen-installed PWA sits flush under the iOS notch and above the home indicator.

#### Breakpoints

| Token | min-width | Use |
|---|---|---|
| `bp.sm` | 640px | Two-column article cards in history |
| `bp.md` | 768px | Side-by-side article + RunTimeline (Mac) |
| `bp.lg` | 1024px | Reserved (no v1 layout depends on it) |

### Surface: `astro-site` (external)

We do not own this codebase. We **align tokens only** so a Minion-generated article looks like the same product when opened on the public site vs the PWA. Source of truth lives in the separate Astro repo at [`allienna/allienna.github.io`](https://github.com/allienna/allienna.github.io) under `veilleur/site/tailwind.config.mjs`. If a token diverges here, fix it here and open a follow-up issue against the Astro repo — never the reverse.

### Surface: `minion` (logs)

No UI. Structured JSON logs only (`runId`, `step`, `level`). No ANSI color; Cloud Logging renders the JSON. The `RunTimeline` in the PWA is the human-visible projection of these logs.

## 4. States

> Conventions every interactive surface must honor. `/review` enforces all five.

### Loading
- **Article fetch** (Today, History): `SkeletonCard` for ≥300ms, never a spinner. Avoids flicker for sub-300ms Firestore reads.
- **Run trigger** (Run-now button): inline spinner inside the button + disabled state. Never block the screen.
- **Live run** (RunTimeline): no spinner — the running step has the `running` status (sky pulse). The pulse *is* the loading affordance.

### Empty
- **No article today** (before 06:15 Europe/Paris or `skipped: no_sources`): `EmptyState` with mascot at 30% opacity, text "Pas d'article aujourd'hui", subline explaining cause (cron not yet run / no source) + `RunNowButton`.
- **No run history**: `EmptyState`, text "Aucun run pour l'instant", no CTA (first cron run will populate).
- **Always text-first**. Illustrations beyond the muted mascot are out of scope for v1.

### Error
- **Run failure** (banner on Today + push notif): `ErrorBanner` at top of view, red strip, message `Run échoué à l'étape <X>`, action `Voir les détails` → `/runs/[id]`. Never auto-dismiss.
- **Auth expired / Gmail revoked**: `ErrorBanner` with action `Voir la procédure` → opens runbook URL.
- **Network error on Run-now**: inline `Toast.error`, retryable. Do not surface a banner for a single transient call.
- **Component crash** (ErrorBoundary): full-page `ErrorBanner` variant with `Recharger` action. Emits a structured log line (`level: "error"`, `event: "pwa.boundary"`, `runId`) to Cloud Logging via the PWA's logging client — the same sink the Minion writes to (constitution §4). No Sentry or other third-party telemetry sink in v1.
- **Recovery is always an affordance.** No dead-end error screens.

### Success
- **Copy LinkedIn post** → `Toast.success` "Post copié", 2s duration.
- **Save image** → `Toast.success` "Image enregistrée", 2s duration. On iOS where the Share API is required, the OS sheet replaces the toast.
- **Run completes** while PWA is open → no toast (would obscure article); the `RunTimeline` last row turning emerald is the confirmation. Push notif handles the "PWA closed" case.
- **No celebratory animations.** Mood = calm.

### Offline / Degraded
- **Service-worker-cached read**: last-known article remains visible offline; `ErrorBanner` (info variant) "Mode hors ligne — article du <date>". History list is cached for the last 7 entries.
- **Firestore unreachable**: read from SW cache; `RunNowButton` disabled with tooltip-replacement caption "Connexion requise".
- **Push subscription expired**: silent retry on next PWA open; no UI flag (operator doesn't need to know).

## 5. Accessibility Baseline

- **Contrast minimum**: WCAG AA (4.5:1 normal, 3:1 large) — non-negotiable, both modes. Every semantic / status token is verified against `bg.default`.
- **Focus management**: `:focus-visible` ring `ring-2 ring-primary ring-offset-2` on every interactive element (inherited from Astro `global.css`). Focus trap inside `Sheet`. Focus restored on close. No `outline: none` without a replacement.
- **Keyboard support**: every action reachable without a mouse, even though primary device is touch. Documented shortcuts in v1: none (no power-user surface).
- **Screen reader**: semantic HTML first. `aria-live="polite"` on the `running` step name so VoiceOver announces step transitions during a live run. `aria-label` on icon-only buttons (RSS link pattern from Astro).
- **Reduced motion**: `prefers-reduced-motion: reduce` disables the `running` pulse (replaced by static dot), Sheet slide-in, and Toast slide-in. All non-essential transitions opt out.
- **Color independence**: status is never communicated by color alone — every `StatusPill` pairs color with the FR status verb (`succès`, `avec avertissements`, `échec`, `ignoré`, `interrompu`, `en cours`).
- **Touch targets**: minimum 44×44pt (iOS HIG) for any tap target. `compact` density does not lower this floor.
- **Locale**: BCP-47 throughout the web surface. `<html lang="fr">` (the short subtag is correct BCP-47 when the region adds nothing). `Intl.DateTimeFormat('fr-FR')` and `Intl.NumberFormat('fr-FR')` for date/cost/duration formatting (region required by Intl). The POSIX-style `fr_FR` is reserved for Open Graph `og:locale` meta (where the OG spec mandates underscore) and any backend log field; it is **never** used in `lang`, `Intl.*`, or HTTP `Accept-Language` headers.

## 7. Integration Contract

Other commands rely on this document. Do not break these contracts when editing:

- **`/specify`** — every UI feature lists which surfaces and components it uses. If a needed component is not in §2 Inventory, `/specify` halts with `DESIGN.md needs /design update for component: <name>`.
- **`/plan`** — cites tokens by name (e.g., `color.status.success`, `text.h2`, `density.list.row`). Never hex literals.
- **`/implement`** — reads §1 Tokens, applies them via Tailwind config or CSS variables. Never invents tokens. Reads §2 Inventory, uses listed shadcn primitives only.
- **`/review`** — verifies that:
  1. No hex/rgb literals in committed UI code (must be tokens).
  2. Every rendered component is in §2 (no ad-hoc components).
  3. The five §4 States are handled for every interactive view.
  4. The §5 a11y baseline holds (focus ring, reduced-motion, color independence, 44pt targets, fr locale).
  5. Astro-aligned tokens (`color.accent.primary`, `color.accent.navy`, fonts) match `../veilleur/site/tailwind.config.mjs`.
